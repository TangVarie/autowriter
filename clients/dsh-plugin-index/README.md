# 写作台插件的索引

DeepSeek Harness 桌面端的「插件索引」：一份 JSON，列出写作台插件有哪些版本、每个版本装哪次提交。运营的桌面端订阅这份索引之后，插件页上能直接安装写作台插件；这边登记了新版本，她那边就出现「有可用更新」，点一下就升级。

> **验证到哪一步**：2026-11-16 在负责人的 Windows 桌面端（0.2.2-rc.3）上走通过一次：添加索引源、认出之前用 Git 地址装的 1.0.0、点更新升到 1.0.1。没验证的是运营的网络读不读得到这个地址，以及 Mac 上的表现。

## 索引地址

```
https://raw.githubusercontent.com/TangVarie/autowriter/claude/xhs-content-workstation-BSEuH/clients/dsh-plugin-index/index.json
```

地址里那段是默认分支的名字。默认分支改名，这个地址就失效，运营那边要换一次。

GitHub 的这个域名在国内不一定稳定。运营读不到的话，退路是让 deskcore 服务器提供同一份文件（要加一条只读路由并部署），那是另一件事，没做。

## 运营一次性要做的

1. 侧栏「插件」→「实验性插件」里把「自定义插件索引」打开。
2. 插件页出现「发现」页签 →「添加索引源」→ 粘贴上面的地址。
3. 在「发现」里找到「写作台」→ 安装。已经用 Git 地址装过的，这里会直接显示已安装或有可用更新。

之后有新版，插件页上会提示，点「更新」即可。

## 发一版（负责人）

1. 改 `clients/dsh-plugin`，**把 `package.json` 的版本号加上去**，照常走 PR、合并。
2. 记下合并出来的那次提交的完整 40 位提交号，然后：

   ```bash
   git fetch origin
   node clients/dsh-plugin-index/release.mjs <提交号>
   ```

   脚本从那次提交里读版本号（不读工作区），登记进 `index.json`。同一个版本号登记过就会拒绝，版本号没比现有的新也会拒绝。
3. 把改过的 `index.json` 提交、走 PR、合并。合并后几分钟（GitHub 有缓存），运营那边刷新插件页就能看到更新。

所以每发一版是两次合并：一次是插件代码，一次是索引。索引必须后合，因为它要写的就是前一次合并出来的提交号。

登记过的版本不要改指向，也不要删：已经装了那个版本的机器靠它判断自己是不是最新。

## 测试

```bash
node --test clients/dsh-plugin-index/test/*.test.js
```

除了格式，还会对每个版本做一次 `git show <提交号>:clients/dsh-plugin/package.json`，核对那次提交里的包名、版本号和 `engines.dsh` 与索引里写的一致。
