# 写作台插件 · DeepSeek Harness

把写作台（deskcore）做成 DeepSeek Harness 桌面端左侧栏的一个入口：**点一下就开一个普通对话**，这个对话的智能体预设是「写作台」。项目规则、发牌、查重、存档只跟着从这个入口开的对话走；普通对话里没有协议，也看不到 `mcp__deskcore__*` 这些工具，只有一句指路。

> **验证到哪一步**：1.0.0 的代码在负责人的 Windows 桌面端（0.2.2-rc.3）里以本地包的形式加载过，侧栏入口和预设都注册成功，普通对话里能看到指路那句。**还没验证**：点入口之后开出对话的实际画面、从入口开第一个对话写一批稿的全流程、预设里那个 MCP 客户端的首次连接、以及从 Git 地址安装这一版。第一次装请由负责人自己来。

## 运营怎么用

1. 装 DeepSeek Harness 桌面端，登录。
2. 侧栏「插件」→「添加插件」→ 粘贴负责人给的安装地址 → 确认安装，然后重启一次桌面端。
3. 在任意对话的输入框里输入一行（地址和钥匙由负责人给），看到「写作台配好了」即可：

   ```
   /desk-setup 地址 钥匙
   ```

4. 以后要写稿：点左侧栏的「写作台」，出来一个对话，直接说「给途鸽写三篇…」。

连没连上，在写作台对话里输入 `/desk-status` 看。

## 负责人要准备什么

- **安装地址**：`git+https://github.com/TangVarie/autowriter.git#<提交号>&path:/clients/dsh-plugin`，提交号用默认分支上的完整 40 位。
- **每人一把钥匙**：照 `docs/deskcore-runbook.md`「加一个写手」加。
- **写作台地址**：deskcore 的网址，带不带 `/mcp` 都行。

**从 0.1.0 升上来**：先在插件页把旧的卸掉，再用新的提交号添加。两个版本不能同时启用——0.1.0 把 deskcore 注册成全局服务，1.0.0 里「看得见 deskcore 的工具就算写作台对话」那条兜底判据会把每一场对话都认成写作台对话。地址和钥匙存在凭据库里，卸载不会丢，不用重新 `/desk-setup`。

## 它做了什么

| 做的事 | 解决什么 |
|---|---|
| 左侧栏一个入口 = 开一个写作台对话 | 不用记命令、不用手选预设 |
| deskcore 的工具挂在「写作台」预设里 | 普通对话不带写作台，连工具都看不见 |
| 协议放进写作台对话的系统提示，每 30 分钟从服务端取一次 | 不用装 skill；协议改了不用重装；长对话压缩不会丢协议 |
| 普通对话的系统提示里一句指路 | 写手没走到写作台、模型直接开写（2026-10-19 那次的形状） |
| 没为这个项目调过 `open_project`，就拦下 `draw_angles` / `check_drafts` / `score_drafts`（旧名 `commit_drafts` 一样拦） | 不开项目就写 |
| 对话压缩之后要求重新 `open_project`，并提醒模型一句 | 压缩把项目规则摘要掉之后接着写 |
| 一轮里查过重却没存档，收尾前催一次 | 写完忘了存档，稿子没有指纹 |
| 没配置、工具没挂上或协议没取到时，系统提示里写明不写稿、该对用户说什么 | 没连上写作台却照样把稿子写出来 |
| 协议前言里注明：服务端说明里关于 skill、核版本、WorkBuddy、`mcp.json` 的说法在这里不适用 | 服务端一个字不用改 |

地址和钥匙存在桌面端自己的凭据库里（`~/.dsh/.credentials.yaml`），不进配置文件，不进会话日志，也不经过模型。

服务端一行没改：用的是现有的 `/mcp` 和 `POST /tool/get_protocol`。WorkBuddy 那条路不受影响。

## 管不到的

- **模型一个工具都不调、直接把稿子写出来**：插件看不到，只靠系统提示里的协议。
- **普通对话里说「给途鸽写一篇」**：模型会被告知去左侧栏开写作台。那一句只是指路，不是硬闸，它也可能先写个大概再提醒。
- **评论**（`comments_for` / `score_comments`）没有加拦截，只靠协议。
- **改版之前开的对话**不带规则，不做兼容：要接着写就从入口重新开一个。
- **别的插件**：DeepSeek Harness 的插件之间没有隔离，同一台机器上的其他插件能读到钥匙、也能在同样的事件上做相反的事。
- **升级插件本身**：从 Git 地址装的插件，换新版要用新的提交号重新添加一次。协议更新不走这条路。

## 维护时要记得

- **「写作台」预设的工具清单是从 DSH 的 `standard` 预设抄的**（shell、读写文件、搜索、子智能体、office、网页、待办、压缩等）。DSH 升级后 `standard` 变了，这份不会跟着变，要人工对照 `@deepseek-ai/dsh-web-app` 的 `presets/standard.patch.yml` 同步一次。
- **`skill-filesystem` 那一行不要加回 `customSkillDirs`**：`standard` 里那行靠 `createRequire` 去解析 DSH 自己的包，从这个包的位置解析不到，会抛错连累整行。
- **不要加构建步骤，也不要加运行时依赖**。从 Git 装的包不会跑构建脚本；`client.js` 是手写的 `window.__ModuleLoader__.load(...)`，它的 `id` 必须和 `package.json` 的包名一致。

## 结构

| 文件 | 作用 |
|---|---|
| `index.js` | 入口，只做 import |
| `lib/desk.js` | 纯逻辑，不依赖 DSH：地址解析、协议拉取、系统提示怎么拼、每个会话的流程状态 |
| `lib/plugin.js` | 接到 DSH 的扩展点上；DSH 的东西都从参数进来，测试里用假的 |
| `presets/writing-desk.patch.yml` | 「写作台」智能体预设：标准工具面 + deskcore 的 MCP 客户端 |
| `client.js` | 浏览器端：侧栏入口，和一个只负责「开对话」的面板 |
| `locale/`、`docs/`、`icon.svg` | 插件页上的标题、说明、图标 |
