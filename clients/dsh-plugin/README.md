# 写作台插件 · DeepSeek Harness

把写作台（deskcore）接进 DeepSeek Harness 桌面端的插件。装上之后，运营不用配 MCP、不用装 skill、不用碰任何文件。

> **状态：没在真实的桌面端里装过。** 逻辑有单元测试（`node --test`），对 DeepSeek Harness 的每个扩展点都是照 0.2.2-rc.3 的源码写的，但这边的环境不能运行桌面端，所以「装得上、连得通、模型照着走」这三件事都还没有实测。第一次装请由负责人自己来。

## 运营怎么装（三步，全在界面里）

1. 装 DeepSeek Harness 桌面端，登录。
2. 侧栏「插件」→「添加插件」→ 粘贴负责人给的安装地址 → 确认安装。
3. 在任意对话的输入框里输入下面这一行（地址和钥匙由负责人给），回车：

   ```
   /desk-setup 地址 钥匙
   ```

   看到「写作台配好了」就完成了。**新开一个对话**开始写。

写作台连没连上，随时输入 `/desk-status` 看。

## 负责人要准备什么

- **安装地址**：`git+https://github.com/TangVarie/autowriter.git#<提交号>&path:/clients/dsh-plugin`，提交号用默认分支上包含这个目录的那次提交的完整 40 位。钉住提交号，以后的推送不会悄悄改变运营机器上跑的代码。
- **每人一把钥匙**：照 `docs/deskcore-runbook.md`「加一个写手」加。
- **写作台地址**：deskcore 的网址，带不带 `/mcp` 都行。

发给运营的就是两行：安装地址，和 `/desk-setup 地址 钥匙`。

## 它做了什么

| 做的事 | 解决什么 |
|---|---|
| 自己注册 MCP 服务（名字 `deskcore`） | 运营不用配 MCP |
| 把协议正文放进系统提示，每 30 分钟从服务端取一次最新的 | 不用装 skill；协议改了不用任何人重装；长对话压缩不会丢协议 |
| 没为这个项目调过 `open_project`，就拦下 `draw_angles` / `check_drafts` / `score_drafts` | 不开项目就写 |
| 对话压缩之后要求重新 `open_project`，并提醒模型一句 | 压缩把项目规则摘要掉之后接着写 |
| 一轮里查过重却没调 `score_drafts`，收尾前催一次 | 写完忘了存档，稿子没有指纹 |
| 没配置或没连上时，系统提示里写明不写稿、该对用户说什么 | 没连上写作台却照样把稿子写出来 |

地址和钥匙存在桌面端自己的凭据库里（`~/.dsh/.credentials.yaml`），不进配置文件，不进会话日志，也不经过模型。

服务端一行没改：插件用的是现有的 `/mcp` 和 `POST /tool/get_protocol`。WorkBuddy 那条路不受影响。

## 管不到的

- **模型一个工具都不调、直接在对话里把稿子写出来**：插件看不到。这种情况只靠系统提示里的协议。
- **评论**（`comments_for` / `score_comments`）没有加拦截，只靠协议。
- **别的插件**：DeepSeek Harness 的插件之间没有隔离，装在同一台机器上的其他插件能读到钥匙、也能在同样的事件上做相反的事。运营的机器上不要装来路不明的插件。
- **升级插件本身**：从 Git 地址装的插件，要换新版得用新的提交号重新添加一次。协议更新不走这条路，所以正常情况下很少需要。

## 改代码

```bash
cd clients/dsh-plugin
node --test test/*.test.js
```

- `lib/desk.js`：纯逻辑，不依赖 DeepSeek Harness。
- `lib/plugin.js`：接到扩展点上，DSH 的东西都从参数进来，测试里用假的。
- `index.js`：入口，只做 import。

没有构建步骤，也没有运行时依赖：从 Git 装的包不会跑构建脚本，所以必须是能直接加载的 JS。
